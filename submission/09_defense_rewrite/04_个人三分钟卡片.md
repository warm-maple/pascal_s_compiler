# 04 个人三分钟卡片

每个人只需要把自己的卡片讲熟。现场不要展开太散，按“我负责的模块、输入输出、核心结构、关键代码、测试或错误样例”五句话组织。

## 郝政伟：整体架构与模块集成

### 3 分钟讲稿

“我负责整体架构与模块集成。这个项目采用典型编译流水线：词法分析、语法分析与 AST 构建、语义分析、代码生成。主控流程在 `src/main.cpp`，入口先解析命令行参数，再清空 parser 状态、符号表和错误处理器，然后调用 `yyparse()` 生成 AST。

语法阶段结束后，主程序会检查是否有词法或语法错误；如果有错误，就打印诊断并退出，不进入语义分析。语义分析通过 `SemanticAnalyzer` 遍历 AST，建立符号表并做类型检查，完成后把符号表交给全局 `g_symbol_table`。只有语义阶段也没有错误时，才调用 `CodeGenerator` 生成 C 代码。

测试方面，平台结果是 95 / 95。本地还有课程自建测试，当前是 16 / 16；严格 C 检查是 9 / 9。我的模块重点不是某一个单独语法点，而是保证这些模块能串成一个稳定的可运行编译系统。”

### 必会代码

- `src/main.cpp:39`，入口
- `src/main.cpp:88`，`yyparse()`
- `src/main.cpp:103`，语义分析
- `src/main.cpp:113`，代码生成

### 兜底回答

问：为什么语义错误后不继续生成 C？

答：“因为语义错误说明 AST 虽然结构上成立，但含义已经不可信。继续生成 C 会把错误扩散到后端，所以主控流程在每个阶段后都检查错误并提前退出。”

## 张睿渤：词法分析与定位支持

### 3 分钟讲稿

“我负责词法分析与定位支持。词法分析器用 Flex 实现，规则写在 `src/lexer.l`。这些规则可以看作词法翻译表：关键字、标识符、整数、实数、字符、字符串、运算符和分隔符都会被映射成 Bison 能识别的 token。

Pascal 语言大小写不敏感，所以关键字规则使用大小写字符类匹配，普通标识符会通过 `strdup_lower()` 转成小写后再传给 parser。注释支持 `{...}`、`(*...*)` 和 `//...`，其中 `(*...*)` 用 Flex 独立状态 `PAREN_COMMENT` 跳过，多行注释会维护行列号。

与语法分析器的接口是 `yylex()`。它返回 token 类型，通过 `yylval` 传递语义值，例如整数值、实数值、标识符字符串；同时通过 `YY_USER_ACTION` 记录 token 起始列，供错误诊断输出源码位置和箭头。”

### 必会代码

- `src/lexer.l:15`，列号维护
- `src/lexer.l:20`，标识符转小写
- `src/lexer.l:38`，注释状态
- `src/lexer.l:56` 到 `90`，关键字规则
- `src/lexer.l:125` 到 `139`，字面量和标识符

### 兜底回答

问：注释会传给 parser 吗？

答：“不会。注释规则只跳过内容并维护行列号，不返回 token，所以 parser 完全看不到注释。”

## 周柄名：语法分析与解析状态

### 3 分钟讲稿

“我负责语法分析与解析状态。语法分析用 Bison 实现，核心文件是 `src/parser.y`。它根据 Pascal-S 的程序结构、声明、类型、语句和表达式产生式进行归约，输出统一的 AST。

parser 的职责是建树，不做符号表和类型检查。例如赋值语句归约成 `AssignmentNode`，数组访问归约成 `ArrayAccessNode`，record 字段访问归约成 `RecordAccessNode`，repeat-until 归约成 `RepeatUntilStatementNode`。对于数组维度、record 字段、参数列表和语句列表这些归约期间需要暂存的信息，我们放在 `ParserState` 里，归约完成后挂到 AST 节点上。

语法错误方面，`yyerror()` 会报告错误并进入 panic-mode。parser 里在声明、参数列表、语句序列和 begin-end 块设置了若干 `error` 产生式作为同步点，所以能在部分缺分号或坏语句后继续分析，输出多个错误位置。”

### 必会代码

- `src/parser.y:185`，程序根节点
- `src/parser.y:294`，类型声明
- `src/parser.y:467`，复合语句
- `src/parser.y:495`，赋值
- `src/parser.y:599` 到 `632`，表达式优先级
- `src/parser.y:730`，`yyerror`
- `src/parser_state.h:9`，解析期状态

### 兜底回答

问：语法分析输出是什么？

答：“输出是 AST，也就是 `root_ast`。后面的语义分析和代码生成都围绕这棵树进行。”

## 蔡禹煊：AST 与公共数据结构

### 3 分钟讲稿

“我负责 AST 与公共数据结构。AST 定义在 `src/ast.h`，它是整个编译器中间表示。parser 负责构建它，semantic 负责检查它，codegen 负责把它翻译成 C。

AST 节点按表达式、语句、声明和程序根节点分层。表达式包括字面量、标识符、数组访问、record 字段访问、二元表达式、一元表达式和函数调用；语句包括赋值、复合语句、if、while、repeat-until、for、过程调用和 write；声明包括变量声明和函数过程声明。

公共数据结构里，`ArrayInfo` 保存数组维度、上下界和元素类型，`RecordInfo` 保存 record 的字段列表，`ParameterInfo` 保存形参类型和是否引用参数。所有阶段通过 Visitor 访问 AST，这样节点结构和阶段逻辑分开，便于维护。”

### 必会代码

- `src/ast.h:16`，类型枚举
- `src/ast.h:37`，数组信息
- `src/ast.h:58`，record 字段
- `src/ast.h:72`，参数信息
- `src/ast.h:84`，AST 基类
- `src/ast.h:474`，Visitor 接口

### 兜底回答

问：为什么节点里要保存行列号？

答：“因为语义分析发现错误时需要回到源码位置输出诊断。parser 构造节点时记录 `line` 和 `column`，错误处理器再用这些信息画箭头。”

## 李良顺：语义分析与符号表

### 3 分钟讲稿

“我负责语义分析和符号表。符号表在 `src/symbol_table.*`，语义分析在 `src/semantic_analyzer.cpp`。符号表采用作用域栈，每一层是一个从名字到符号条目的 map。条目里保存类型、作用域层级、offset、常量标记、引用参数标记、数组信息、record 信息、函数参数和返回类型。

语义分析使用 Visitor 遍历 AST。遇到变量声明就插入符号表，遇到函数或过程先把函数头注册到全局作用域，再进入新作用域插入参数和局部变量。查找标识符时从当前作用域向外查，这样能支持局部屏蔽。

检查内容包括未声明标识符、重复声明、赋值左右类型兼容、常量不能赋值、数组下标必须是 integer、record 字段必须存在、函数过程调用参数数量和类型匹配、`var` 参数必须是左值、if/while/repeat 条件类型以及 for 循环变量类型。”

### 必会代码

- `src/symbol_table.cpp:27`，插入
- `src/symbol_table.cpp:42`，查找
- `src/symbol_table.cpp:91`，类型兼容
- `src/semantic_analyzer.cpp:88`，数组检查
- `src/semantic_analyzer.cpp:120`，record 检查
- `src/semantic_analyzer.cpp:248`，赋值检查
- `src/semantic_analyzer.cpp:478`，程序级语义分析顺序

### 兜底回答

问：为什么要先注册所有函数头？

答：“这样函数体或主程序里可以调用前面已经声明的子程序。先把函数名、返回类型和参数表放进全局符号表，再检查普通声明和函数体，调用检查时名字就可见。”

## 孔力帆：类型系统与错误诊断支持

### 3 分钟讲稿

“我负责类型系统和错误诊断支持。类型推断相关逻辑主要在 `src/type_resolver.cpp` 和 `TypeSystem`。`resolve_expr_type()` 会根据表达式节点推断类型：字面量直接返回固定类型，标识符查符号表，数组访问返回元素类型，record 字段访问返回字段类型，函数调用返回函数返回类型，二元表达式再根据运算符和左右类型推断结果。

record 的字段解析单独由 `resolve_record_info()` 和 `find_record_field()` 处理，可以支持多级字段访问。比如 `point.inner.y` 会先找到 `point` 的 record 信息，再找 `inner` 字段对应的嵌套 record，最后找 `y`。

错误诊断在 `src/error.*`。主程序会预读源码行，错误处理器保存错误类型、信息、行列和长度，打印时输出 `[Semantic Error] line ...`，再输出源码行和箭头。语法错误还配合 panic-mode 做有限恢复，同一位置重复错误会去重。”

### 必会代码

- `src/type_resolver.cpp:7`，查字段
- `src/type_resolver.cpp:16`，解析 record 信息
- `src/type_resolver.cpp:50`，表达式类型推断
- `src/error.cpp:67`，打印错误和箭头
- `src/error.cpp:102`，错误去重和上限

### 兜底回答

问：类型推断和语义检查有什么区别？

答：“类型推断回答表达式是什么类型，语义检查判断这个类型在当前上下文是否合法。比如 `1.5` 推断为 real，而赋给 boolean 是否允许，是语义检查里的兼容性判断。”

## 吴锡华：目标代码输出验证与测试支撑

### 3 分钟讲稿

“我负责目标代码输出验证和测试支撑。代码生成的核心文件是 `src/codegen.cpp`，输入是已经通过语义检查的 AST 和符号类型信息。实现方式是源到源翻译，用 Visitor 遍历 AST 并输出 C 代码。

几个关键映射是：Pascal 变量和常量生成 C 声明，数组生成 C 数组并对下界做平移，record 生成 C struct，函数和过程生成 C 函数，`var` 参数生成指针，`write/read` 生成 `printf/scanf`，`repeat-until` 生成 `do-while` 且条件取反。Pascal 函数返回值通过给函数名赋值实现，生成 C 时改写为 `_retval`。

测试方面，`course_tests/run_course_tests.ps1` 会对成功样例执行 Pascal-S 到 C、GCC 编译、运行和输出对比，对错误样例检查诊断关键片段。`run_strict_c_checks.ps1` 会用严格 C11 参数编译生成的 C。当前结果是课程测试 16 / 16，严格检查 9 / 9。”
