# 03 老师追问速答

## 一、符号表

### 1. 你们符号表里存了什么？

答：

“一条符号表记录对应一处声明，主要存名字、类型、作用域层级、offset、是否常量、是否 `var` 引用参数、数组信息、record 字段信息、函数/过程参数表和函数返回类型。这样语义分析和代码生成都能通过同一个入口拿到声明信息。”

### 2. 符号表是什么结构？

答：

“是作用域栈。外层是 `vector`，每一层是 `unordered_map<string, SymbolEntry>`。进入函数或过程时压栈，退出时弹栈。查找从当前作用域向外找，所以局部变量可以屏蔽外层同名变量。”

### 3. 插入怎么处理重复声明？

答：

“`insert()` 只检查当前作用域是否已有同名符号。如果当前层存在就返回 false，语义分析据此报重复声明。不同作用域允许同名，这是作用域屏蔽。”

### 4. 查找怎么处理嵌套作用域？

答：

“从 `scopes.size() - 1` 开始往 0 查，先命中最近的局部声明，找不到再到全局。这样符合 Pascal 里局部优先的名字绑定规则。”

### 5. 你们的定位和重定位怎么讲？

答：

“定位分两层：符号定位由 `lookup()` 找到对应 `SymbolEntry`，源码定位由 AST 节点的 `line/column` 和 `ErrorHandler` 输出。重定位不是机器码里的重定位，因为我们生成 C；项目里更接近重定位的是作用域 offset 重置和数组下界平移，例如 Pascal 的 `array[3..5]` 在 C 里访问时变成 `arr[(i)-(3)]`。”

## 二、词法分析

### 6. 词法分析怎么实现？

答：

“用 Flex。`lexer.l` 中每条正则规则把源程序词素映射为 Bison token，同时把具体值写入 `yylval`。例如整数写 `ival`，实数写 `dval`，标识符和字符串写 `sval`。”

### 7. 翻译表在哪里？

答：

“Flex 规则就是翻译表。关键字规则返回 `PROGRAM/VAR/BEGIN` 等 token，字面量返回 `INTEGER_LITERAL/REAL_LITERAL`，运算符和界符返回对应 token，普通标识符统一转小写后返回 `IDENTIFIER`。”

### 8. 注释怎么处理？

答：

“支持三种注释：`{...}`、`(*...*)`、`//...`。它们都不产生 token。`(*...*)` 用 Flex 的独立状态 `PAREN_COMMENT` 处理，多行注释会维护行列号，保证后续错误定位不偏。”

### 9. Pascal 大小写不敏感怎么做？

答：

“关键字用大小写字符类匹配，比如 `[Pp][Rr]...`。普通标识符通过 `strdup_lower()` 统一转成小写，所以后续语法和语义阶段只处理统一名字。”

### 10. 词法分析和语法分析怎么连接？

答：

“Bison 的 `yyparse()` 会不断调用 Flex 生成的 `yylex()`。`yylex()` 返回 token 编号，具体语义值通过全局 `yylval` 传递，行列号通过 `yylineno` 和 `yycolumn_start` 提供给 parser 和错误模块。”

## 三、语法分析

### 11. 语法分析方法是什么？

答：

“用 Bison 生成 LALR 风格的自底向上语法分析器。parser 根据产生式归约，同时构造 AST 节点。语法分析的输出是 `root_ast`，不是 C 代码。”

### 12. 为什么不在 parser 里做语义检查？

答：

“为了让模块职责清楚。parser 只判断结构是否合法并建 AST；标识符是否声明、类型是否兼容放在 `SemanticAnalyzer` 里。这样错误定位和代码维护更清楚，也更符合经典编译器前端分层。”

### 13. 能检测哪些语法错误？

答：

“主要包括声明缺分号、变量声明格式错误、参数列表错误、begin-end 块结构错误、语句序列错误、表达式结构错误、函数/过程调用括号或逗号错误等。Bison 会报 `syntax error`，我们会附带源码行和箭头。”

### 14. 语法错误能恢复吗？

答：

“能做有限恢复。`yyerror()` 进入 panic-mode，若遇到 parser 中的 `error` 产生式同步点，例如声明末尾、参数组、语句序列、复合语句结束位置，就调用 `finish_syntax_recovery()` 退出 panic-mode，继续分析后续片段。”

### 15. AST 怎么构建？

答：

“每个归约动作里创建对应节点，例如赋值生成 `AssignmentNode`，if 生成 `IfStatementNode`，数组访问生成 `ArrayAccessNode`，record 字段访问生成 `RecordAccessNode`。节点会保存源码行列，后续语义错误可以定位。”

## 四、AST 与公共结构

### 16. AST 为什么要用 Visitor？

答：

“因为同一棵树要被多个阶段遍历。语义分析和代码生成的行为不同，但节点结构相同。Visitor 把节点结构和阶段行为分离，后续新增节点时只需要补对应 visit 方法。”

### 17. 数组信息放在哪里？

答：

“数组类型信息在 `ArrayInfo`，里面有每个维度的上下界、总大小和元素类型。parser 在解析数组声明时填这个结构，语义分析检查下标，代码生成用它计算 C 数组大小和下界平移。”

### 18. record 信息放在哪里？

答：

“record 用 `RecordInfo` 表示，字段用 `RecordField` 表示。字段可以是普通类型、数组，也可以继续嵌套 record。代码生成会递归收集 record 并输出 C struct。”

## 五、语义分析

### 19. 语义分析怎么实现？

答：

“`SemanticAnalyzer` 继承 `ASTVisitor`，遍历 AST。遇到声明就插入符号表，遇到表达式和语句就查符号表、推断类型并检查约束。错误统一交给 `ErrorHandler`。”

### 20. 支持哪些类型？

答：

“主要支持 integer、real、boolean、char、array、record、function、procedure。字符串字面量主要用于 `write` 和字符串常量输出，不作为完整 Pascal string 类型参与一般变量系统。”

### 21. 有哪些类型兼容规则？

答：

“相同类型兼容，integer 可以隐式兼容到 real。其他方向不自动兼容，例如 real 不能赋给 boolean，real 也不能隐式赋给 integer。”

### 22. 表达式检查了什么？

答：

“逻辑运算要求 boolean，当前 `not` 也允许 integer 以兼容平台用例；`div` 和 `mod` 要求 integer；加减乘和 `/` 要求 numeric；关系运算要求左右类型可兼容，结果是 boolean。”

### 23. 数组检查了什么？

答：

“检查数组名是否声明、是否真的是数组、下标个数是否等于维度数、每个下标表达式是否为 integer。边界值主要用于代码生成下界平移，不做运行时越界检查。”

### 24. record 检查了什么？

答：

“检查被访问对象是不是 record，字段名是否存在。多级字段通过 `resolve_record_info()` 一层层解析，例如 `point.inner.y` 先解析 `point` 的 record 信息，再找 `inner`，再找 `y`。”

### 25. 函数和过程调用检查了什么？

答：

“检查名字是否声明、类型是否 callable、实参数量是否一致、实参类型是否和形参兼容。对于 `var` 参数，还要求实参必须是可赋值左值，比如变量或数组元素，不能是常量表达式。”

### 26. 语句检查了什么？

答：

“赋值检查左值和左右类型兼容；if/while/repeat 条件要求 boolean-compatible；for 循环变量、起始和结束表达式要求 integer；常量不能被赋值。”

## 六、代码生成

### 27. 代码生成输入是什么？

答：

“输入是已经通过语义分析的 AST，以及语义阶段生成的符号表和类型信息。主程序只有在没有错误时才会调用 `CodeGenerator::generate()`。”

### 28. 采用什么技术？

答：

“采用源到源翻译，也就是把 Pascal-S 翻译成 C 代码。实现上还是 Visitor 遍历 AST，不生成汇编或目标文件。”

### 29. 基本映射规则是什么？

答：

“integer 到 int，real 到 float，boolean 到 int 或 C 布尔表达式，char 到 char；数组到 C 数组，record 到 struct，函数过程到 C 函数，read/write 到 scanf/printf，while/for/if 基本对应 C 控制流。”

### 30. repeat-until 怎么生成？

答：

“Pascal 的 `until` 是退出条件，C 的 `while` 是继续条件，所以生成 `do { ... } while (!(condition));`。”

### 31. 函数返回值怎么生成？

答：

“Pascal 里函数通过给函数名赋值表示返回值。生成 C 时函数内部引入 `_retval`，遇到对当前函数名赋值就改写成 `_retval = ...`，函数结尾 `return _retval`。”

### 32. var 参数怎么生成？

答：

“形参生成指针，例如 `int* x`，调用时传地址，例如 `swap(&arr[0], &arr[1])`，函数内部访问引用参数时解引用。语义阶段先保证传入的是左值。”

### 33. 代码生成阶段怎么处理错误？

答：

“原则上代码生成只接收已经通过语义检查的 AST，所以大部分错误在前面阶段停止。`ErrorHandler` 保留 codegen 错误类型，但当前核心策略是前置检查，避免错误输入进入 codegen。”

## 七、测试与演示

### 34. 平台 95 / 95 说明什么？

答：

“说明公开和隐藏评测里覆盖的基础 Pascal-S 翻译任务都能通过。但我们不只依赖平台结果，还补了本地课程测试和严格 C 检查来验证可复现性和生成代码质量。”

### 35. 课程自建测试怎么验证？

答：

“成功样例会走 Pascal-S 编译、生成 C、GCC 编译、运行、输出对比。错误样例会运行编译器并检查诊断输出中包含期望关键片段。”

### 36. 严格 C 检查有什么价值？

答：

“它用 `-std=c11 -pedantic-errors -Wall -Wextra -Werror` 这类严格参数编译生成 C，验证生成结果不仅能跑，也尽量符合 C 标准和警告约束。”

### 37. 为什么有 `course_tests` 和 `user_tests` 两套？

答：

“`course_tests` 是正式自建测试集，包含成功和错误样例以及自动化脚本；`user_tests` 更像开发过程中的快速回归样例，用于手动演示基础功能。”

## 八、容易被追问的风险题

### 38. 你们是不是完整 Pascal 编译器？

答：

“不是。项目目标是 Pascal-S 子集到 C 的源到源编译器，覆盖课程要求的主要语法和语义功能，并扩展了 record、repeat-until 和错误定位。没有实现完整 Pascal 标准库、运行时越界检查或机器码生成。”

### 39. 有运行时错误恢复吗？

答：

“没有做运行时错误恢复。错误恢复主要在编译阶段，尤其是语法 panic-mode 恢复。语义错误会收集诊断后停止，不继续生成 C。”

### 40. 为什么 boolean 有时按 int 生成？

答：

“为了和平台用例以及 C 输出兼容，boolean 在类型系统里是独立类型，但目标 C 里用 int 或布尔表达式承载。输出格式也用 `%d`，这样更稳定。”

### 41. 为什么字符串不是完整类型？

答：

“课程基础 Pascal-S 子集重点不是 string 变量系统。当前支持字符串字面量和字符串常量输出，主要服务 `write` 场景，没有扩展成完整字符串赋值和运算。”

### 42. 数组越界检查了吗？

答：

“编译期检查了数组维度数量和下标类型，没有做运行时越界检查。数组上下界用于生成 C 数组大小和访问下标平移。”

### 43. record 支持多级嵌套吗？

答：

“支持。`RecordInfo` 里字段可以持有嵌套 `RecordInfo`，type resolver 会逐级解析字段，codegen 会先输出内层 struct 再输出外层 struct。”

### 44. 代码生成为什么要用临时变量？

答：

“函数调用实参里如果有副作用，或者涉及引用参数取址，直接展开可能导致求值顺序不稳定。代码生成会保留临时变量机制，把实参先绑定后调用，降低 C 求值顺序差异带来的问题。”

### 45. 如果老师问某个成员具体写了什么，怎么答稳？

答：

“不要说自己独立写了所有相关代码。可以说：‘我负责这一模块的讲解、维护和验收准备，核心实现我理解为三点……，代码位置是……，我可以打开对应函数说明。’ 然后直接讲输入、输出、数据结构和错误样例。”
