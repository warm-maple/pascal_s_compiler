# 验收答辩重写材料

这套材料是按 2026 年 5 月 20 日现场验收来准备的，目标是不依赖原有 `submission/07_defense` 讲稿，而是直接围绕当前代码、测试结果和老师问题清单组织。

使用顺序：

1. 先看 `01_总讲稿与演示流程.md`，确定现场怎么开场、怎么演示、每一步说什么。
2. 再看 `02_代码讲解索引.md`，把老师可能点名问的代码位置提前在 IDE 里打开。
3. 每个人看 `04_个人三分钟卡片.md`，只背自己模块的 3 分钟口径和兜底问答。
4. 最后用 `03_老师追问速答.md` 做模拟提问。

当前验证结论：

- 当前源码重新构建通过：`cmake --build build-mingw2`
- 课程自建测试通过：`Passed 16 / 16`
- 生成 C 严格检查通过：`Strict C checks passed 9 / 9`
- 平台结果口径：Educoder `95 / 95` 全部通过，截图在 `docs/presentation/assets/educoder_95_95_crop.png`

关于是否继续补源码注释：

不建议在验收前继续大面积改源码注释。当前关键模块已经有足够现场讲解用的注释，继续改源码有引入无关 diff 和构建风险的可能。更稳的做法是把本目录作为“讲解索引”，现场老师问到哪里，就打开对应文件和函数讲实现。

口径底线：

不要编造提交历史，也不要说某个人“独立写完某模块的每一行”。更稳的表达是“我负责讲解和维护这一块，核心实现思路是……，对应代码在……”。每个人至少要能回答自己卡片里的输入、输出、关键数据结构和一个错误样例。
