## 二、组长 3 分钟总述

建议原文：

“老师好，我们组实现的是一个 Pascal-S 到 C 的源到源编译器。整体流程是：Flex 做词法分析，Bison 做语法分析并构建 AST，之后独立的语义分析阶段维护符号表并做类型检查，最后代码生成模块把通过检查的 AST 翻译成 C 代码，再由 GCC 编译运行。

从结果上看，项目已经在 Educoder 平台达到 95 / 95 全部通过。本地我们还补了一套课程自建测试，成功样例会完整走 Pascal-S 到 C、C 编译、运行和输出对比，错误样例会检查诊断信息；当前课程自建测试是 16 / 16，严格 C 检查是 9 / 9。

功能上，基础部分支持变量、常量、函数、过程、数组、表达式、控制流、读写语句和函数返回值。扩展部分支持 `record` 结构和多级字段访问、`repeat ... until`、带源码定位箭头的错误诊断，以及语法阶段的有限 panic-mode 恢复。

分工上，郝政伟负责整体架构与集成；张睿渤负责词法分析与定位支持；周柄名负责语法分析和解析状态；蔡禹煊负责 AST 与公共数据结构；李良顺负责语义分析和符号表；孔力帆负责类型系统和错误诊断支持；吴锡华负责目标代码输出验证、测试支撑和使用说明整理。接下来我们可以按模块展示代码和运行结果。”

### 3. 成功样例演示：record、多级字段访问

命令：

```powershell
New-Item -ItemType Directory -Force -Path .\defense_demo_work | Out-Null
.\build-mingw2\pascc.exe .\course_tests\success\record_nested_access.pas -o .\defense_demo_work\record_nested_access.c
& 'C:\Code\mingw64\mingw64\bin\gcc.exe' -std=c99 .\defense_demo_work\record_nested_access.c -o .\defense_demo_work\record_nested_access.exe
.\defense_demo_work\record_nested_access.exe
```

预期输出：

```text
7
```

打开生成的 C：

```powershell
Get-Content .\defense_demo_work\record_nested_access.c
```

可讲重点：

- Pascal 的 `record` 被翻译成 C 的 `struct`
- 内层 `record` 先生成 `struct pas_record_1`，外层再引用它
- `point.inner.y` 直接生成 C 字段访问
- 输出 `7` 来自 `point.x := 3` 和 `point.inner.y := point.x + 4`

### 4. 成功样例演示：数组下界重定位

命令：

```powershell
.\build-mingw2\pascc.exe .\course_tests\success\array_lower_bound_shift.pas -o .\defense_demo_work\array_lower_bound_shift.c
& 'C:\Code\mingw64\mingw64\bin\gcc.exe' -std=c99 .\defense_demo_work\array_lower_bound_shift.c -o .\defense_demo_work\array_lower_bound_shift.exe
.\defense_demo_work\array_lower_bound_shift.exe
Get-Content .\defense_demo_work\array_lower_bound_shift.c
```

预期输出：

```text
123
```

生成 C 里要指出：

```c
int arr[3];
arr[(3) - (3)] = 1;
arr[(4) - (3)] = 2;
arr[(5) - (3)] = 3;
```

讲法：

“Pascal 数组可以从 3 开始，但 C 数组从 0 开始，所以代码生成阶段把访问下标做了平移。这里 `array[3..5]` 生成 `int arr[3]`，访问 `arr[i]` 时生成 `(i) - (3)`。”

### 5. 成功样例演示：var 参数

命令：

```powershell
.\build-mingw2\pascc.exe .\course_tests\success\var_parameter_array_element.pas -o .\defense_demo_work\var_parameter_array_element.c
& 'C:\Code\mingw64\mingw64\bin\gcc.exe' -std=c99 .\defense_demo_work\var_parameter_array_element.c -o .\defense_demo_work\var_parameter_array_element.exe
.\defense_demo_work\var_parameter_array_element.exe
Get-Content .\defense_demo_work\var_parameter_array_element.c
```

预期输出：

```text
91
```

生成 C 里要指出：

```c
void swap(int* x, int* y);
swap(&arr[0], &arr[1]);
*x = *y;
```

讲法：

“Pascal 的 `var` 参数对应引用传递。代码生成时形参用指针，实参传地址，函数内部访问时解引用。这也解释了为什么语义分析阶段要检查 `var` 实参必须是左值。”

### 6. 错误样例演示：语义错误

命令：

```powershell
.\build-mingw2\pascc.exe .\course_tests\errors\semantic_assignment_type_mismatch.pas -o .\defense_demo_work\semantic_assignment_type_mismatch.c
```

预期输出：

```text
[Semantic Error] line 5, col 10: Type mismatch in assignment: cannot assign real to boolean
        flag := 1.5;
             ^
```

讲法：

“这里语法是正确的，但赋值左右类型不兼容。语义分析通过 `get_expr_type` 得到左边是 boolean、右边是 real，`TypeSystem::is_compatible` 不允许 real 到 boolean，所以报语义错误，并且主控流程不会继续生成 C。”

### 7. 错误样例演示：语法恢复

命令：

```powershell
.\build-mingw2\pascc.exe .\course_tests\errors\syntax_recovery_multiple.pas -o .\defense_demo_work\syntax_recovery_multiple.c
```

预期输出：

```text
[Syntax Error] line 4, col 1: syntax error
    begin
    ^~~~~

[Syntax Error] line 6, col 5: syntax error
        write(x);
        ^~~~~
```

讲法：

“这个样例故意少分号。Bison 发现语法错误后进入 panic-mode，部分 `error` 产生式会在声明或语句边界同步，所以不是第一个错误后直接崩溃，而是能继续报告后续错误位置。”

## 四、老师按问题清单问时的总回答框架

### 符号表

“符号表条目记录名字、类型、作用域层级、offset、是否常量、是否引用参数、数组信息、record 字段信息、函数参数和返回类型。整体结构是一个作用域栈，栈中每层是 `unordered_map<string, SymbolEntry>`。插入只插当前层，查找从内层向外层找，进入函数或过程时压入新作用域，退出时弹出。”

### 词法分析

“词法分析用 Flex。`lexer.l` 的规则就是翻译表，正则匹配到关键字、标识符、字面量、运算符和界符后返回 Bison token，同时通过 `yylval` 传语义值。注释支持 `{...}`、`(*...*)` 和 `//...`，都跳过不产生 token。接口是 `yylex()`，语法分析器 `yyparse()` 持续调用它。”

### 语法分析

“语法分析用 Bison，自底向上归约，输出是 AST。parser 不做类型检查，主要负责把程序结构、声明、表达式、语句和函数过程组织成节点。语法错误通过 `yyerror` 和 `error` 产生式报告，能检测缺分号、声明格式错误、表达式结构错误、参数列表错误、begin-end 块错误等，并输出带源码行和箭头的位置。”

### 语义分析

“语义分析使用 ASTVisitor 遍历 AST。主要工作是建立符号表、绑定标识符、检查类型和上下文约束。支持 integer、real、boolean、char、array、record、function、procedure。检查包括未声明、重复声明、赋值兼容、数组下标、record 字段、函数/过程参数个数和类型、var 参数左值、if/while/repeat 条件、for 变量和起止表达式等。”

### 代码生成

“代码生成输入是已经通过语义检查的 AST 和全局符号表。采用源到源翻译，用访问者模式把 AST 节点映射成 C 代码。变量和常量生成 C 声明，数组按维度生成 C 数组并处理下界平移，record 生成 struct，函数过程生成 C 函数，var 参数用指针，read/write 生成 scanf/printf，repeat-until 生成 do-while 的反条件。”
