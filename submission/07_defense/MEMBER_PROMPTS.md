## 三、张睿渤：词法分析

### 你至少要能稳定说清

1. `flex` 根据正则规则生成词法分析器
2. 词法分析负责把字符流切成 token 流
3. 关键字、标识符、字面量、运算符都在这一层识别
4. 这里还记录了行号和列号，用于错误定位和恢复后的继续报错

### 一句提示词

“词法分析解决的是‘这串字符是什么 token’，同时为后续错误提示提供位置基础。”

### 可能被问

- 为什么用 `flex` 而不是手写状态机？
- Pascal-S 关键字大小写怎么处理？
- 行列号为什么在词法阶段记录？

## 四、周柄名：语法分析与解析状态

### 你至少要能稳定说清

1. `bison` 根据文法规则生成语法分析器
2. parser 不只是判语法对错，还会在归约动作里构建 AST
3. `ParserState` 用于维护解析期上下文，减少静态全局状态
4. 在分号、`END`、`UNTIL` 等同步点附近支持语法 panic-mode 恢复
5. 最终会生成统一的 AST，供后续阶段使用

### 一句提示词

“语法分析负责把 token 流按文法归约成 AST，这棵树就是后续语义分析和代码生成共享的中间表示。”

### 可能被问

- 什么是 AST？
- 为什么要用 AST，而不是解析完直接生成代码？
- 解析状态为什么要单独管理？
- 语法错误后为什么还能继续报下一处？

## 五、蔡禹煜：AST 与公共数据结构

### 你至少要能稳定说清

1. AST 是程序结构化之后的中间表示
2. 节点包括常量、标识符、表达式、赋值语句、控制流、函数调用、数组访问、record 字段访问等
3. Visitor 模式让不同阶段都能统一遍历 AST
4. AST 是编译器前后端之间的重要桥梁

### 一句提示词

“AST 的作用是把 Pascal-S 程序变成统一的树结构，让语义分析和代码生成都可以基于同一份程序结构工作。”

### 可能被问

- AST 和语法树有什么关系？
- Visitor 模式为什么适合这里？
- 为什么 record、数组、函数调用都要单独有节点？

## 六、李良顺：语义分析与符号表

### 你至少要能稳定说清

1. 语法正确不代表程序语义正确
2. `SymbolTable` 管理变量、常量、函数、参数及其作用域
3. `SemanticAnalyzer` 负责做标识符绑定、类型检查、参数检查等
4. 典型错误包括未声明标识符、赋值类型不匹配、参数错误、record 字段不存在

### 一句提示词

“语义分析负责判断这棵 AST 在含义上是否成立，而符号表和作用域机制是它的核心支撑。”

### 可能被问

- 什么是作用域栈？
- 为什么符号表要从内层向外查找？
- 参数检查和赋值检查分别怎么做？

## 七、孔力帆：类型系统与错误诊断支持

### 你至少要能稳定说清

1. 类型系统负责回答“这个表达式最终是什么类型”
2. `TypeResolver` 集中处理表达式类型、数组元素类型和 record 字段类型
3. 错误诊断会输出错误类型、行列号、源码行和定位箭头
4. 语法阶段用 panic-mode 恢复抑制报错雪崩，并继续扫描后续同步点
5. caret diagnostics 依赖词法阶段记录位置和主程序缓存源码行

### 一句提示词

“类型系统保证不同模块使用一致的类型规则，错误诊断则把这些检查结果清晰地反馈给用户。”

### 可能被问

- 为什么要单独做 `TypeResolver`？
- 为什么错误提示能显示源码和箭头？
- 你们的错误恢复是完全继续编译，还是局部同步后继续找错？
- `record` 字段访问的类型是怎么查出来的？
