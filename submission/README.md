# 验收交付目录

这个目录用于整理课程设计最终验收需要提交的全部材料，目标是让代码、报告、表格、可运行程序和测试材料形成一套可直接打包/回填模板的交付结构。

## 对应老师要求

附件 3 的提交资料清单要求：

1. 附件1：课程设计报告（分组表）
2. 附件2：课程设计报告
3. 源程序
4. 可运行程序
5. 测试用例
6. 程序使用说明（运行环境、使用方法等）

## 当前目录映射

```text
submission/
  01_group_form/      附件1：分组表相关材料
  02_report/          附件2：正式课程设计报告
  03_source/          源程序交付说明
  04_binary/          可运行程序交付说明

  06_user_guide/      程序使用说明
  DELIVERY_CHECKLIST.md

```

## 推荐工作方式

### 1. 先用 Typst/Markdown 组织内容

原因：

- 结构更稳定，便于版本管理
- 多人协作时比直接改 Word 更可控
- 最终可以导出 PDF 做展示版

### 2. 最后再回填 Word 模板

原因：

- 老师提供的附件1/附件3本质上是固定格式表格
- 如果验收时明确要求 Word，那么只需要把这里整理好的内容回填
- 不建议一开始就在 Word 里写正式正文

### 3. 不要把 build/临时文件混入交付目录

最终交付应只包含：

- 源码
- 可运行程序
- 测试材料
- 报告/表格/说明文档

不应包含：

- `build-*`
- 本地截图缓存
- `~flex_temp_*`
- `~m4_*`
- 临时压缩包
