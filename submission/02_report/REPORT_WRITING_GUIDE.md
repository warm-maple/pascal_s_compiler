# 正式报告写作说明

正式报告模板（附件2）要求的章节非常明确，建议直接按以下顺序推进：

## 1. 先写什么

优先写：

1. 课程设计任务和目标
2. 总体设计
3. 详细设计
4. 程序测试

原因：

- 这些内容你手里已经有大量现成材料
- 依赖项目当前代码结构最强

## 2. 后写什么

后写：

1. 需求分析
2. 源程序清单
3. 课程设计总结

原因：

- 这些更适合在结构稳定后统一收束

## 3. 不建议做的事

- 不要把整份报告直接写成“开发日志”
- 不要逐文件流水账式介绍
- 不要在正文大段粘贴源码

## 4. 建议写法

建议以“编译流水线 + 模块协作”为主线组织内容：

1. 输入源码如何进入系统
2. 词法分析如何切分 token
3. 语法分析如何构造 AST
4. 语义分析如何建立符号表并检查类型
5. 代码生成如何输出 C
6. 测试如何验证正确性
