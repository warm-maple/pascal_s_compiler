# 编译原理与技术课程设计：Pascal-S 语言编译程序测试计划

## 1. 测试目标与范围

### 1.1 测试目标
本测试计划旨在验证“Pascal-S 语言编译程序”的正确性、健壮性与稳定性。通过系统化的单元测试与集成测试，确保编译程序能够：
1. **正向验证**：正确解析合法的 Pascal-S 源程序，并将其等价转换为可编译、可执行的 C 语言目标代码。
2. **逆向验证（容错性）**：准确检测词法、语法、语义各阶段的非法输入，精确定位错误位置，并执行错误恢复策略，避免编译器崩溃。
3. **平台达标**：通过头歌实践教学平台（EduCoder）的公开测试集与隐藏测试集考核。

### 1.2 测试范围
测试覆盖编译程序的全生命周期，具体包括五个核心测试域：
* **词法分析测试**：Token 识别、注释过滤、忽略大小写边界测试。
* **语法分析测试**：文法推导验证、AST（抽象语法树）构建、复合语句嵌套。
* **错误处理与恢复测试**：恐慌模式、同步词法单元集合验证、报错精准度测试。
* **语义分析与符号表测试**：作用域管理、类型相容性、`factor -> id` 多义性消歧。
* **目标代码生成测试**：Pascal-S 语义向 C 语言结构的映射正确性及最终运行结果校验。

## 2. 测试环境与工具栈选型

根据前期技术方案调研与确定，本项目的开发与测试环境如下：
* **前端开发工具**：Flex（词法生成器） + Bison（语法生成器）
* **目标语言环境**：GCC
* **测试形式**：
  * **白盒测试**：通过断点调试或打印 Log，验证符号表的逻辑层次（`locate`, `insert`, `relocate` 操作）及 AST 生成的正确性。
  * **黑盒测试**：给定 `source.pas`，验证系统是否输出正确的报错信息或 `target.c` 代码。
* **线上评测平台**：头歌实践教学平台（EduCoder）。

## 4. 各阶段测试用例设计规划

本节明确了各模块需要覆盖的典型测试场景。在后续开发阶段，各组员需根据此大纲将测试点转化为具体的 `.pas` 源码文件。

### 4.1 词法分析测试用例规划 (Lexer Tests)
* **正例测试 (TC-LEX-01)**：验证大小写不敏感特性（如 `ProGram`、`PROGRAM`、`program` 均识别为 `PROGRAM_TOKEN`）。
* **正例测试 (TC-LEX-02)**：复杂注释的静默过滤（如 `{ This is a \n multi-line comment }`，验证不影响后续 Token 且行号计算准确）。
* **反例测试 (TC-LEX-03)**：非法字符拦截（如输入 `@`、`$` 或非法的数字标识符 `123abc`），验证是否输出词法报错并忽略非法字符继续扫描。

### 4.2 语法分析与错误恢复测试规划 (Parser & Error Tests)
* **正例测试 (TC-PAR-01)**：多层复合语句嵌套（`begin begin ... end; end.`），验证嵌套深度支持。
* **反例测试 (TC-ERR-01, 核心难点)**：**恐慌模式错误恢复**（组员3主导）。构造缺失分号 `;` 或 `if` 后缺少 `then` 的语句。验证编译器是否能精准报错行号，并跳过错误片段直到下一个同步符号（如分号或 `end`），**保证编译器不崩溃，并能继续报出后续的语法错误**。

### 4.3 语义分析与符号表测试用例规划 (Semantic Tests)
* **正例测试 (TC-SEM-01, 核心难点)**：`factor -> id` 多义性消歧。用例中定义常量 `a`、简单变量 `b`、无参函数 `c`。在赋值语句中调用它们，验证系统是否能通过查询符号表准确赋予常量值、右值或执行函数调用。
* **反例测试 (TC-SEM-02)**：子程序非嵌套限制。在 `procedure` 内部尝试定义 `function`，验证编译器是否报错拒绝。
* **反例测试 (TC-SEM-03)**：**防止报错雪崩**。使用一个未声明的变量 `x`，引发未声明报错。验证符号表是否隐式插入了一个虚拟变量 `x`，使得后续代码再次使用 `x` 时不再引发一连串的“未声明”或“类型不符”报错。
* **边界测试 (TC-SEM-04)**：函数参数传值/传址（var 参数）类型严格匹配校验。

### 4.4 目标代码生成与集成测试规划 (CodeGen Tests)
* **功能验证 (TC-CG-01)**：编写求最大公约数（GCD）小程序，编译生成 C 语言代码，利用 GCC 编译并运行，输入 `12, 18`，验证输出结果是否为 `6`。
* **控制流验证 (TC-CG-02)**：`for` 循环与 `if-else` 的深层嵌套翻译，验证生成的 C 代码是否存在括号不匹配或逻辑短路问题。

## 5. 测试验收标准 (通过条件)

本编译器的最终验收必须同时满足以下三个层级的标准：

1. **基本功能达标**：组内单元测试用例全部执行通过，无内存泄漏，无严重崩溃（Crash）缺陷。
2. **容错能力达标**：面对包含错误的源程序，能输出清晰的 `<行号, 列号> + 错误原因`，并能成功执行至少 1 次错误恢复，继续完成编译流程。
3. **平台硬性指标**（严格对标课件 46 页要求）：
   * 头歌平台**公开测试集（open_set，共 70 个）**：正确通过率 ≥ 85%（即通过至少 60 个）。
   * 头歌平台**隐藏测试集（hidden_set，共 25 个）**：正确通过率 ≥ 60%（即通过至少 15 个）。
